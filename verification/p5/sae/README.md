## Families, split and the FVU rule

Four non-protective HarmBench/sorry-bench families, 32 refusal prompts each,
deterministic stride; self-harm and sexual-content families are excluded from
capture permanently (`docs/PLAN-NEXT.md`, 2026-11-18). Split: sorted by id, every
4th row held out (24 train / 7-8 held out per family; the held-out ids are in
`train-report.json`).

Baseline rule (plan): `fvu < 1.0` (beat the train-mean predictor) **and**
`fvu < pca_control_fvu` (beat the best rank-k linear reconstruction fitted on the
same train rows, k = the SAE's active features). The published FVU is the median
over three seeds and the published checkpoint is the median-FVU seed; the per-seed
values and the spread are in `train-report.json`. With 7-8 held-out rows a single
seed's FVU is noise, and publishing the best seed would be selection on the test
set.

Capacity is set by the row count, not the budget: `capacity-sweep.json` measures
nine candidates and `features=128, k=2` is the smallest dictionary that beats the
rank-2 control in all four families (k=4 wins 2/4, k=8 wins 1/4 — a larger active
set only gives the control more to match). Cross-family held-out FVU (each
dictionary scored on the next family's rows) is 0.774-0.811, i.e. the dictionaries
transfer about as well as they fit — they are not family-idiosyncratic, but they
are also explaining only a fifth of the variance.

## Feature table

`feature-table.md` / `feature-table.json`: for each family, the top 12 features by
`|mean activation on refusal rows - mean activation on compliant rows|`, with both
means, the active fraction on each side, and `cos_to_axis` — the cosine between
the feature's unit decoder direction and the refusal-minus-compliant mean axis in
the same standardised space. `jdewitt/sae.py` requires that number next to any
feature a downstream arm ablates: a cosine near 1 means the feature is the
contrast axis again, not a new thing.

What the table actually shows, in the order a reader needs it:

- The **largest** contrasts are compliant-selective, not refusal-selective:
  `-22.6` to `-28.7` for one feature per family that fires on 0.91-0.97 of the
  compliant rows and 0.04 of the refusal rows. The biggest dictionary direction
  separates harmless compliance from harmful refusal — the "is this request a
  refusal trigger" direction, not per-family refusal features.
- The refusal-selective side is small and sparse: the strongest positive contrasts
  are `+2.7` (illegal), `+2.5` (cybercrime), `+3.6` (non-violent crimes), `+5.3`
  (violence), each active on 0.04-0.17 of the refusal rows (1-4 of 24).
- **No feature is the contrast axis**: `max |cos_to_axis| = 0.383` over all 48
  published features, so nothing here is the rank-1 direction the contrast fit
  already removes. That is the property `jdewitt/sae.py` says a feature needs to be
  a new thing — it is not yet evidence that it carries behaviour.

The compliant side is the 32 harmless rows the capture labelled `good` — real
jailbreak deliveries on this lineage are 3-5 rows in total, so a per-family
delivery side cannot be built, and this card says so rather than pretending the
proxy is a delivery. Any delivery-axis claim therefore stays GATED.

## Reproduce

```
uv run python scripts/p5_sae_suite.py --out verification/p5/sae/inputs/suite.jsonl
uv run python -m jdewitt.cli capture ... (see the table above)
uv run python scripts/p5_sae_train.py --records verification/p5/sae/inputs/records.pt \
  --dump-residuals --out verification/p5/sae --features 128 --k 2 --steps 1200 \
  --batch 16 --seeds 20261123,20261124,20261125 --device xpu --rerun-check
```

`--rerun-check` trains the published seed twice and compares weight digests; all
four families matched. The trainer enables `torch.use_deterministic_algorithms(True)`:
without it XPU runs at one seed differ by ~1e-6 and a digest comparison is
meaningless. The committed residual matrix is float32 — exactly the captured bf16
values widened — because an fp16 copy is lossy at ~2e-4 and moved one family's
FVU across the baseline rule in this card's own first attempt.
`digests.json` pins the record file, the residual matrix, the report, the feature
table and every checkpoint.

## What this does not establish

Nothing about refusal behaviour or removal. The dictionaries are a feature basis
over captured residuals, and the row count (24 train rows per family against a
2,048-wide residual stream) is the binding limit — the sweep shows which capacities
are identifiable at this row count, not what an SAE would show with a real corpus.
A large `|contrast|` in the table is a pre-registration input, not a result.
